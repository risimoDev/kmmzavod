# Автопилот (новая «Фабрика») — монтаж → уникализация → ферма телефонов

Цель: один раз настроить автоматизацию на **проект** и запустить. Дальше система
каждый день, несколько раз в день, без участия человека:

1. берёт исходники из библиотеки проекта (сначала свежие, потом пул);
2. пишет **новый AI-сценарий** под ролик (OpenRouter) и озвучивает (Fish Audio);
3. делает **умный монтаж** под озвучку (apps/editor, авто-подтверждение раскадровки);
4. **уникализирует** результат в N копий (по числу аккаунтов);
5. **публикует** копии через **ферму телефонов** (authMethod=device) по окнам времени.

Старые «Factories» (HeyGen-пресеты) и «Кампании» остаются как есть — Автопилот
отдельный раздел (решение заказчика 2026-10-07).

| Вопрос | Решение |

## Ментальная модель

**1 окно публикации ≈ 1 монтаж → N уникальных копий → N аккаунтов.**
Каждый аккаунт в окне получает свою копию; два аккаунта никогда не получают
одинаковый файл, и один аккаунт никогда не получает две копии одного монтажа.

- DEMAND = `аккаунтов × окон_в_день`.
- SUPPLY = буфер готовых неопубликованных копий + копии «в производстве».
- Луп (scheduler, 60с) держит буфер на `bufferWindows` окон вперёд.

## Модель данных

- `Autopilot` — настройки (проект, режим монтажа, AI, уникализация, аккаунты,
  окна `publishTimes[]` в `timezone` с `jitterMinutes`), состояние (`nextWindowAt`,
  `lastError`), статистика.
- `AutopilotBatch` — один производственный цикл (машина состояний):
  `pending → scripting → analyzing → rendering → uniquifying → ready | failed`
  (+ ссылки `editProjectId`, `uniquifyJobId`, `sourceVideoIds[]`, `script`).
- `AutopilotRun` — журнал тиков (produce / distribute / error) для наблюдаемости.
- `DistributeJob.autopilotId` — кто создал раздачу.
- `SourceVideo.origin` (`upload | editor | autopilot`) — чтобы выходы монтажа не
  попадали обратно в пул исходников.

## Конвейер (продвигается опросом в scheduler — самовосстанавливается)

| Шаг | Где | Что |
|---|---|---|
| pending → scripting | worker `autopilot-produce` | выбор исходников, сценарий (OpenRouter), TTS (Fish), длительность MP3 → EditProject (mix, 1 клип, replace audio, длина = озвучка) → editor-analyze |
| analyzing → rendering | scheduler | EditProject `ready` → оставить лучший клип → editor-render |
| rendering → uniquifying | scheduler | EditProject `completed` → UniquifyJob(preserve_context, субтитры уже вшиты) → uniquify-analyze |
| uniquifying → ready | scheduler | UniquifyJob `completed` |
| ready → (раздача) | scheduler, окно | по 1 копии каждому пригодному аккаунту-телефону |

Таймауты: батч, застрявший на шаге > 90 мин, помечается failed (луп создаст новый).
Ошибки подряд ≥ 3 → автопилот в `error` + уведомление (не жжём ресурсы впустую).

## Публикация по окнам (исправляет баги Кампаний)

- Окна `publishTimes` в часовом поясе автопилота + случайный сдвиг ±`jitterMinutes`.
- На окно аккаунт получает **≤ 1** пост. «Сегодня» считается в TZ автопилота и
  включает **уже запланированные** (pending/scheduled/publishing) элементы — нет
  двойных постов, если прошлое окно ещё публикуется.
- Пригодность: device + deviceId + isActive + health ≥ minHealth + не shadowban +
  warmup (если группа требует).

## Фазы

1. **Движок автопилота** (этот этап): схема+миграция, очередь+воркер, луп,
   API, UI `/autopilot` (мастер + страница с пульсом, батчами, журналом).
2. **Монтаж**: в редакторе два явных продукта «под уникализацию из одного видео» /
   «из нескольких видео»; seed/исключение уже использованных фрагментов для
   разнообразия; кэш анализа исходников (не гонять Whisper по пулу каждый раз).
3. **AI-студия**: ключи на сервере (AdminSetting) вместо localStorage, единый
   AI-стек для редактора и уникализации, озвучка на клип (а не на проект),
   выбор/ротация голосов, библиотека сценариев и хуков.
4. **Уникализация**: убрать фингерпринт `comment=variant_N`, рандомизировать
   метаданные/энкодер/GOP/битрейт, pHash по нескольким кадрам + проверка
   похожести вариантов между собой перед публикацией, больше векторов
   (кадрирование, скорость, оверлеи), quality-gate.
5. **Обратная связь**: метрики постов → веса выбора фрагментов/стилей.

## Фаза 2 — Монтаж (детально, 2026-10-07)

Найденные проблемы движка (apps/editor):
1. Микс детерминирован: одни и те же исходники → один и тот же монтаж (нет seed,
   нет памяти об использованных фрагментах) → автопилот плодит почти-дубли.
2. В режиме озвучки (replace) отбор всё равно на 30% по речи источника, которая
   выбрасывается — нужен визуальный скоринг.
3. Материала меньше, чем озвучки → видео короче голоса → обрезается CTA;
   наоборот → тишина в хвосте.
4. Каждый анализ заново гоняет Whisper по пулу, даже когда звук будет заменён.
5. Переходы в миксе определяются по `title == "Mix"` — переименование клипа ломает монтаж.
6. Микс в режиме «ориг. звук» режет речь на 4-сек куски посреди фразы.
7. Нет явных продуктов «под уникализацию из 1 / из N видео» и отправки в уникализацию.

Решения:
- **Движок отбора v2**: seed + взвешенный стохастический выбор (качество + разнообразие),
  K вариантов монтажа за один анализ с штрафом за повтор фрагментов, `exclude_ranges`
  (уже использованное), темп (calm/normal/fast), скоринг по режиму звука,
  баланс исходников, «хук первым», порядок: keep → хронология, replace → чередование.
  Keep-режим режет по границам фраз. Точная длина под цель (с учётом переходов).
- **Рендер**: явные geometry/seed/transitions; replace — видео подгоняется под голос
  (лёгкое замедление ≤ 1.25× или зацикливание) и обрезается до голоса + хвост.
- **Кэш анализа** по storageKey (analysis_version + transcribed); Whisper по
  исходникам не запускается, когда звук заменяется.
- **Продукты в редакторе**: «Под уникализацию · из одного видео» (K разных
  перемонтажей одного ролика), «Под уникализацию · из нескольких видео» (K миксов),
  «Готовый ролик». Кнопки «🎲 другие варианты» и «⚡ отправить в уникализацию».
- **Автопилот**: seed от батча, exclude_ranges из прошлых монтажей, темп, кэш анализа.

### Итог фазы 2 (проверено)

- Отбор (select.py `build_mix_variants`): 3 исходника → 3 варианта по 30.00с, общих
  фрагментов между вариантами одного запроса 0–7%, другой seed → 47% пересечения,
  с exclude_ranges повторно использован 1 кадр из 14; темп calm ≈3.0с/кадр, fast ≈1.6с.
- Keep-режим: кадры строго по границам фраз (Whisper на реальной русской речи),
  субтитры корректно пересчитаны на новую таймлинию, без переходов.
- Рендер e2e (ffmpeg): микс 3 видео + озвучка 21.6с → ролик ровно 22.40с (голос + 0.8с).
- Кэш: повторный анализ тех же исходников 1.4с против 15.2с.
- OpenCV без Haar-каскадов больше не обнуляет анализ движения.

## Фаза 3 — AI-студия (детально, 2026-10-07)

Найденные проблемы:
1. **Запасной сценарий захардкожен под плойку**: «локоны за пять секунд», «заказала»,
   «девчонки» — для пылесоса/наушников получается бред. Включается МОЛЧА при любой
   ошибке OpenRouter (и в автопилоте тоже) → в ленту уходит чушь.
2. **Род рассказчика не учитывается**: промпт пишет «заказала», а голос мужской.
3. **Хронометраж по константе 2.05 слова/с** (в уникализации — 2.6): у каждого голоса
   и скорости свой темп; добивка до длины — шаблонные фразы про «прелесть».
4. **Нет памяти о прошлых хуках** → автопилот повторяет одни и те же заходы.
5. **Один провайдер** (бесплатный каскад OpenRouter, часть моделей устарела, deepseek-r1
   возвращает <think>), GPTunnel в системе есть, но не используется как резерв.
6. **Fish Audio молча подменяет голос** на дефолтный, если voiceId не найден.
7. **Ключи в localStorage браузера** + поле «свой ключ» в UI; автопилот их не видит.
8. **Озвучка одна на проект** — на все клипы (хайлайты разной длины, K вариантов).
9. **Субтитры озвучки из Whisper** — бренды/названия искажаются, хотя текст известен.
10. Код сервисов продублирован в api и orchestrator (≈1500 строк).

Решения:
- Пакет **`@kmmzavod/ai`** (без зависимостей, fetch): цепочка LLM-провайдеров
  OpenRouter → GPTunnel, сценарист с валидацией длины (повторный запрос, обрезка
  середины с сохранением хука и CTA), род рассказчика из голоса, анти-повтор хуков,
  ротация архетипов хука, ровно N уникальных подписей, Fish TTS без подмены голоса,
  каталог голосов, калибровка темпа речи по каждому голосу (AdminSetting VOICE_PACE).
- Шаблон — универсальный (без товара-заглушки), только по явному разрешению
  (ручная работа в студии); автопилот без LLM — ошибка, а не мусор в ленте.
- **Озвучка на клип** (edl.voiceover), «озвучить все клипы» с прогрессом.
- **Субтитры по тексту сценария** на таймингах Whisper (выравнивание).
- Превью голосов, статус провайдеров, ключи только на сервере.

## Фаза 4 — Уникализация (детально, 2026-10-07)

Найденные проблемы (apps/video-processor montage.py + uniquify-воркеры):
1. **Отпечатки в метаданных**: `comment=variant_N` в каждой копии; у всех одинаковое
   «iPhone 15 Pro / QuickTime 17.5.1», а в видеопотоке SEI-блок x264 с версией и всеми
   параметрами (одинаковый у всех копий и противоречит «айфону»); remix пишет `Lavf`;
   дата съёмки вычисляется линейно от seed.
2. **Одинаковое кодирование** всех копий (CRF, preset, GOP, битрейт звука).
3. **Звук почти не меняется**: темп ±1.5% + EQ, без сдвига тона — аудио-отпечаток
   (Chromaprint-подобный) совпадает.
4. **Картинка**: только центр-кроп 1.5–3.5% и ±2% цвета, без сдвига/поворота/обрезки.
5. **Remix зеркалит 50% копий** — надписи и логотипы на товаре задом наперёд.
6. **Уникальность не измеряется**: pHash одного кадра; нет сравнения с исходником и
   между копиями — неизвестно, отличаются ли копии на самом деле.
7. AI уникализации на отдельном стеке (GPTunnel), запасные подписи «Видео (Вариант N)».

Решения:
- **Рецепт уникальности** (`uniqueness.py`): все параметры варианта от seed —
  кадрирование со смещением, поворот, цвет/оттенок, зерно, скорость, обрезка начала/
  конца, рамка с размытым фоном (опц.), сдвиг тона звука, EQ; кодирование (CRF, GOP,
  B-кадры, preset, битрейт/частота звука); метаданные из пула устройств, случайная дата.
- **Гигиена файла**: без SEI x264 (filter_units), bitexact (нет Lavf/Lavc), без comment.
- **Зеркало — только по явному разрешению**.
- **Измерение уникальности**: подпись из 8 кадров (dHash 256 бит) + аудио-отпечаток
  (энергия полос, Haitsma–Kalker); расстояние до исходника и до ближайшей копии;
  слабые копии помечаются и не публикуются автопилотом.
- **AI уникализации** на `@kmmzavod/ai`: подписи — ровно N разных; сценарий remix —
  writeScript; озвучка — Fish (если голос из каталога Fish), иначе GPTunnel TTS.

## Фаза 5 — Обратная связь по метрикам (детально, 2026-10-07)

Найдено:
1. **Метрики не собираются вообще**: нет таблицы, сборщика, эндпоинтов у publisher /
   device-agent. Автопилот выбирает подачу/голос/исходники вслепую (round-robin).
2. **Публикация через телефон не подтверждается**: device-agent открывает окно
   «Поделиться» в приложении и через 3 с возвращает ok — нажатие «Опубликовать» не
   автоматизировано, статус «опубликовано» может не соответствовать действительности.
3. Нет защиты от «мёртвых» аккаунтов (теневой бан → 0 просмотров, а контент продолжает идти).

Решения:
- **Сбор**: device-agent `POST /stats/profile` — открывает профиль, читает сетку
  постов через `uiautomator dump` (просмотры на плитках, закреплённые, подписчики).
  Снимки по расписанию (каждые ~6 ч, пока постам < 4 дней) + ручной ввод в UI.
- **Подтверждение публикации**: пост сопоставлен с плиткой профиля → `verifiedAt`;
  расхождение «опубликовано N, на профиле M» → предупреждение.
- **Нормализация**: perf = ln((views+10)/(медиана аккаунта+10)) — размер аккаунта не
  искажает выводы.
- **Обучение**: Thompson sampling по «рукам» (подача сценария, голос, исходник);
  лучшие хуки — примеры для сценариста; аналитика по часам публикации.
- **Защита**: 3 поста подряд < 30 просмотров за сутки → здоровье аккаунта −15

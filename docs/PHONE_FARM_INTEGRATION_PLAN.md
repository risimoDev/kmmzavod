# Интеграция реальной телефонной фермы (Laixi) — план

## Зачем

Сейчас приватная публикация (`authMethod=private`) идёт через `apps/publisher`
(instagrapi / tiktok-uploader) — программная эмуляция клиента, без реального
устройства. У пользователя есть физическая ферма Android-телефонов дома,
управляемая **Laixi Master** (группконтроль по USB). Реальный телефон с
реальным приложением Instagram/TikTok на реальном IP — существенно более
устойчив к антибот-детекту, чем instagrapi/tiktok-uploader.

Цель: добавить третий метод публикации `authMethod=device`, который дёргает
конкретный физический телефон в домашней ферме через Laixi.

## Топология

```
┌────────────────────── Сервер (VPS, Linux) ───────────────────────┐
│  nginx / api / web / postgres / redis / minio                    │
│  orchestrator (BullMQ workers)                                   │
│    └─ publish.worker: authMethod=device → deviceAgentService     │
│                              │ HTTP POST /publish                │
│                              │ (10.13.13.1 ← AmneziaWG →10.13.13.2)│
│  amneziawg (обфусцированный WireGuard, контейнер или systemd)    │
└────────────────────────────┬──────────────────────────────────────┘
                              │ AmneziaWG туннель (UDP, обфускация трафика)
┌────────────────────────────┴──────────────────────────────────────┐
│  Домашний ПК (Windows) — куда физически подключены телефоны      │
│  amneziawg-client (интерфейс 10.13.13.2)                          │
│  apps/device-agent (Node.js, слушает 10.13.13.2:8300)              │
│    └─ HTTP /publish {deviceId, videoUrl, caption, platform}        │
│         → скачивает видео из presigned MinIO URL                   │
│         → Laixi WS API ws://127.0.0.1:22221/                      │
│            action=httpdown  (закачать видео на телефон)            │
│            action=ExecuteAutoJs (запустить Autox.js-сценарий       │
│              открытия приложения + публикации поста)                │
│            action=screenshot / GetAllinfo (проверка результата)     │
│  Laixi Master ── USB-хаб ── N физических Android-телефонов        │
└──────────────────────────────────────────────────────────────────┘
```

**Почему через VPN, а не напрямую:** Laixi слушает WS API на `127.0.0.1:22221`
(localhost домашнего ПК) — снаружи недоступен в принципе, и пробрасывать порт
из дома в интернет небезопасно (это открывает управление живыми телефонами).
AmneziaWG даёт серверу «частный IP» домашнего ПК внутри зашифрованного
туннеля — `device-agent` слушает только на VPN-интерфейсе, наружу (в реальный
интернет) ничего не торчит. AmneziaWG выбран вместо ванильного WireGuard из-за
обфускации трафика (полезно, если провайдер/сеть блокирует обычный WG).

## Компоненты, которые добавляем

1. **`infra/amneziawg/`** — конфиг сервера (docker-compose service) +
   инструкция генерации клиентского конфига для домашнего ПК.
2. **`SocialAccount.deviceId`** — новое поле (id устройства в Laixi),
   `authMethod='device'`.
3. **`apps/device-agent`** — отдельное Node-приложение, разворачивается на
   домашнем ПК (НЕ в docker-compose сервера — ему нужен доступ к локальному
   Laixi процессу на Windows). HTTP-мост между оркестратором и Laixi WS API.
4. **`apps/orchestrator/src/services/device-agent.ts`** — клиент, зеркалит
   `publisher.ts`; вызывается из `publish.worker.ts` веткой
   `authMethod==='device'`, аналогично существующей `isPrivate`-ветке.
5. **Autox.js-сценарии** (`apps/device-agent/scripts/*.js`) — UI-автоматизация
   открытия Instagram/TikTok на конкретном телефоне: открыть приложение →
   создать пост → выбрать видео из галереи (после `httpdown`) → вставить
   подпись → опубликовать.
6. **API/UI** — `account-farm.routes.ts` + `/farm` страница: возможность
   указать `authMethod=device` + `deviceId` (id из Laixi) на аккаунте.

## Laixi API (то, что подтверждено документацией docs.laixi.app)

- Протокол: WebSocket, `ws://127.0.0.1:22221/` (только на ПК, где стоит
  Laixi Master; auth в доках не описан — предполагаем "все, кто достучался
  до localhost, доверены", отсюда необходимость VPN, а не публичного порта).
- Формат сообщений: `{"action": "<Name>", "comm": {...}}`.
- Нужные нам action'ы: `httpdown` (скачать файл по URL прямо на телефон,
  видимо через Laixi, не через ПК-диск), `Upload the file` (закачать локальный
  файл на устройство), `ExecuteAutoJs` / `StopAutoJs` (`comm.deviceIds`,
  `comm.filePath` — путь к .js на ПК), `screenshot`, `GetAllinfo` (список
  устройств/статусы), `adb` (сырые ADB-команды), `Launch APP`, `Current
  Activity` (для проверки, что пост открылся/закрылся).
- **Не подтверждено доками (нужно проверить руками на месте)**: точный формат
  ответа WS (что возвращает `ExecuteAutoJs`, синхронно ли), нужна ли
  авторизация/токен, доступность WS API в вашей лицензии Laixi (может быть
  платная функция), точный список deviceId в вашей инсталляции.

## Фазы

- **Фаза 0 (этот проход)**: схема БД, туннель, device-agent HTTP-каркас,
  orchestrator-роутинг, UI-поля. Всё, что можно написать и типопроверить без
  доступа к реальным телефонам.
- **Фаза 1 (на месте, у пользователя)**: поднять AmneziaWG между сервером и
  домашним ПК, запустить `device-agent` на Windows, подключиться к реальному
  Laixi WS, откалибровать `deviceId`, написать/подобрать рабочие Autox.js
  сценарии под конкретные версии приложений IG/TikTok на телефонах (это
  единственная часть, которую нельзя сделать вслепую — UI-автоматизация
  завязана на реальные экраны).
- **Фаза 2**: warmup/anti-ban для device-аккаунтов, health-score с реальных
  телефонов (батарея, память), метрики в фермовский dashboard.

## Известные риски

- Autox.js-сценарии хрупкие к версиям приложений/лейаутам — потребуют
  итерации на реальных телефонах, я не могу их протестировать удалённо.
  Дизайн: сценарии текстозаменяемые (плейсхолдеры `{{FILE_PATH}}`,
  `{{CAPTION}}`), логика проверки статуса — по возвращаемому скриншоту/activity.
  Держите Autox.js документацию (kkevsekk1/AutoX на GitHub) под рукой при
  калибровке.
- Один `device-agent` = один домашний ПК/один Laixi. Если появится второй
  дом/вторая ферма — понадобится `deviceAgentUrl` per-account вместо одного
  общего `DEVICE_AGENT_URL`. Не усложняем сейчас.
- Laixi WS без явной авторизации в доках → безопасность целиком на VPN
  (никто снаружи туннеля не должен видеть 10.13.13.0/24).
